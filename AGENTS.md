# Prisma Press — AGENTS.md

## Quick start

```bash
npm install
cp .env.example .env        # fill in real values
npx prisma generate         # generates client to generated/prisma/
npm run dev                 # tsx watch src/server.ts
npm run build               # tsc -> dist/
npx prisma migrate dev      # create/apply migrations
npx prisma migrate deploy   # apply in prod
npx prisma studio           # GUI data browser
npx stripe listen --forward-to localhost:8000/api/subscription/webhook
```

## Architecture

Express 5 + TypeScript (strict, ESNext, moduleDetection:force). Feature-based modular layout:

```
src/
  server.ts                 # entrypoint: connect DB, start listening
  app.ts                    # Express app setup, routes, error middleware
  config/index.ts           # env vars (dotenv loaded here)
  lib/prisma.ts             # PrismaClient singleton with adapter-pg
  lib/stripe.ts             # Stripe instance
  middleware/               # auth(), premiumGuard(), globalErrorHandler, routeNotFoundHandler
  module/<name>/            # one directory per domain
    <name>.route.ts         # Router with route definitions
    <name>.controller.ts    # catchAsync wrappers around service calls, sendResponse
    <name>.service.ts       # business logic + Prisma queries
    <name>.interface.ts     # TS interfaces for payloads/query params
  utils/                    # catchAsync, jwtUtils, sendResponse
```

### Routes (mounted in app.ts)

| Prefix                     | Handler               |
|----------------------------|-----------------------|
| `/api/users`               | userRoute             |
| `/api/auth`                | authRoute             |
| `/api/posts`               | postRoute             |
| `/api/comments`            | commentRoute          |
| `/api/subscription`        | subscriptionRouter    |
| `/api/premium`             | premiumRoute          |
| `POST /api/subscription/webhook` | raw body BEFORE `express.json()` |

## Prisma client — critical

**The client is NOT `@prisma/client` from npm.** It is generated locally to `generated/prisma/` via:

```prisma
generator client {
  provider = "prisma-client"
  output   = "../../generated/prisma"
}
```

Imports use relative paths:

```ts
import { PrismaClient } from "../../generated/prisma/client";
import { UserRole } from "../../generated/prisma/client";       // enums also re-exported here
import { PostStatus } from "../../generated/prisma/enums";
import { PostWhereInput } from "../../generated/prisma/models";
```

`generated/` is in `.gitignore` — always run `npx prisma generate` after clone or schema change.

## Prisma schema

Split across `prisma/schema/` (not a single file):

```
prisma/schema/
  schema.prisma      # generator + datasource (postgresql)
  user.prisma, post.prisma, comment.prisma, profile.prisma, subscription.prisma, enum.prisma
```

`prisma.config.ts` at root (generated by Prisma 7) uses `defineConfig` — NOT a traditional `schema.prisma` at root.

## Auth

JWT-based via `auth(...requiredRoles)` middleware. Token picked from:
1. `req.cookies.accessToken`, or
2. `Authorization: Bearer <token>`, or
3. raw `Authorization` header

Result attached as `req.user: { id, name, email, role }`.

`premiumGuard()` middleware checks for **active** subscription before allowing premium post access.

## Module conventions

- Controllers: wrapped with `catchAsync` (try/catch -> `next(error)`).
- Responses via `sendResponse(res, { success, statusCode, message, data, meta? })`.
- Owner checks done in service layer (authorId vs admin).
- `prisma.$transaction()` used where atomicity matters (e.g., view count + post fetch).
- Pagination: `page`, `limit`, `sortBy`, `sortOrder` query params.

## Notable config

- `tsconfig.json`: `include` is commented out (defaults to `src/`), `exclude: ["node_modules", "dist"]`, `noUncheckedIndexedAccess: true`.
- `noUncheckedSideEffectImports: true` — imports with side effects must be explicitly handled.
- Stripe webhook route receives `express.raw({ type: "application/json" })` — must be BEFORE `express.json()`.
